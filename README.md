# Flights Globe (Next.js)

Web app that plots my flight history on an interactive globe.

## Data

`data/flights.csv` is the source of truth — one row per flight, columns
`date,src,dest,flightno`. `data/airports.json` maps each airport code to its
name and coordinates.

`scripts/build-data.mjs` validates the pair and emits `data/flights.json`
(gitignored, regenerated by `predev`/`prebuild`). `lib/flight-data.js` imports
that JSON, so there's no database, no native module, and no filesystem access
at request time.

## Getting started

```bash
npm install
npm run dev
```

## Adding flights

Append a row to `data/flights.csv` — locally, or in the GitHub web editor from
any device. Pushing to `master` deploys.

```csv
date,src,dest,flightno
2026-09-14,buf,ord,ua3441
```

Dates should be ISO `YYYY-MM-DD`; `M/D/YY` is accepted and normalized. Airport
codes must exist in `data/airports.json` or the build fails with the offending
line numbers — the check that used to be a SQLite `FOREIGN KEY` constraint.

`npm run data:fmt` rewrites both files in canonical form: ISO dates, lowercase
codes, flights in chronological order, airports sorted by code.

## Deployment

Deployed on Vercel from `master`. The API routes are statically prerendered, so
the data is baked into the build and a log change ships on the next deploy.

## Scripts

- `npm run dev` / `npm run build` – `predev`/`prebuild` regenerate `data/flights.json` first.
- `npm run data:build` – validate the log and regenerate `data/flights.json`.
- `npm run data:fmt` – canonicalize `flights.csv` and `airports.json` in place.
- `npm run lint` – Next.js lint.
